# Code Review & Quality

## 리뷰 우선순위

1. **버그/정확성** — 로직 오류, 엣지케이스 누락, 타입 불일치
2. **보안** — XSS, 인증 누락, 민감 정보 노출
3. **가독성** — 이름이 의도를 드러내는가, 복잡도가 필요 이상인가
4. **성능** — 불필요한 재렌더, N+1, 큰 번들
5. **스타일** — 포맷터가 잡아야 할 것은 리뷰에서 언급하지 않음

## 자주 잡히는 문제

- `useEffect` 의존성 배열 누락/과다
- 이벤트 리스너 cleanup 없음
- `any` 타입 남용
- 하드코딩된 URL/값 (환경변수로)
- `console.log` 배포 코드에 잔존

## 리뷰 어조

- "이렇게 하면 안 됩니다" X → "이렇게 하면 Y 문제가 생깁니다. Z로 바꾸면 어떨까요?" O
- 칭찬도 남긴다 — 좋은 코드는 좋다고 말할 것

## 셀프 리뷰 체크리스트

- [ ] 변수/함수명이 의도를 표현하는가
- [ ] 불필요한 주석/console.log 제거했는가
- [ ] 에러 핸들링 있는가 (외부 API 호출 등)
- [ ] 모바일에서 동작 확인했는가
