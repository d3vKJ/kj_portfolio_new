# Idea Refinement

## 아이디어 → 요구사항 변환

막연한 아이디어를 받으면 이 세 질문으로 좁힌다:

1. **누가 쓰는가?** — 방문자 페르소나 (채용담당자, 동료 개발자, 클라이언트)
2. **성공은 무엇인가?** — 방문자가 사이트를 보고 뭘 해야 성공인가 (연락, 포트폴리오 공유, 채용)
3. **꼭 필요한가?** — 없으면 목적을 못 달성하는가

## 포트폴리오 아이디어 필터

| 아이디어 | 질문 |
|---------|------|
| 다크모드 토글 | 없으면 채용에 영향? → 시스템 기본값으로 충분 |
| 프로젝트 필터 | 프로젝트 10개 미만이면? → 필요 없음 |
| 방문자 카운터 | 채용담당자에게 신뢰를 주는가? → 오히려 역효과 가능 |
| 애니메이션 인트로 | 콘텐츠 도달 시간 늦어지지 않는가? → 신중히 |

## 기능 축소 방법

"X를 만들고 싶어" → "X의 가장 단순한 버전은?"
- 인터랙티브 이력서 → 잘 정리된 PDF
- 블로그 → 프로젝트 상세 페이지
- 다국어 지원 → 영어 하나 완성 후

## 메모 형식

아이디어 정제 결과:
```
기능: [이름]
목적: [방문자가 이것을 보고 어떤 행동을 하는가]
MVP: [가장 작은 버전]
보류: [나중에 추가할 것]
```
