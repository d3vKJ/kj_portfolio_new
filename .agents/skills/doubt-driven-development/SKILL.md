# Doubt-Driven Development

## 의심해야 할 순간

- "이렇게 하면 당연히 될 것 같은데" → 테스트해보기
- "다들 이렇게 하지" → 근거 확인
- "나중에 쓸 것 같아서" → YAGNI
- "빠를 것 같아서 최적화" → 측정 먼저

## 포트폴리오에서 자주 틀리는 가정

| 가정 | 실제 |
|------|------|
| 모바일에서 잘 보일 것이다 | 직접 확인 안 하면 보통 깨짐 |
| 이미지가 빠르게 로드될 것이다 | 최적화 안 하면 느림 |
| 애니메이션이 자연스럽다 | 저사양 기기에서 버벅임 |
| SEO가 잘 될 것이다 | 메타태그 누락이 흔함 |
| 링크가 모두 작동한다 | 배포 후 깨진 링크 흔함 |

## 코드 작성 전 질문

1. 이미 존재하는 코드가 있는가?
2. 더 단순한 방법은 없는가?
3. 이것이 실제로 필요한가?
4. 사이드이펙트는 없는가?

## PR 전 질문

1. 내가 만든 코드를 나는 이해하는가?
2. 모바일에서 확인했는가?
3. 콘솔 에러 없는가?
4. 빌드 통과하는가?
