# Using Agent Skills

## 이 프로젝트의 스킬 목록

| 스킬 | 언제 사용 |
|------|-----------|
| `web-design-guidelines` | 디자인 결정할 때, 레이아웃/색/타이포 기준 필요할 때 |
| `frontend-ui-engineering` | 컴포넌트 구조, 상태 관리 방식 결정할 때 |
| `design-taste-frontend` | "이 디자인 괜찮은가?" 판단이 필요할 때 |
| `performance-optimization` | 사이트가 느릴 때, Lighthouse 점수 올릴 때 |
| `security-and-hardening` | 환경변수, API 키, 외부 서비스 연동할 때 |
| `shipping-and-launch` | 배포 전 마지막 체크할 때 |
| `git-workflow-and-versioning` | 커밋 메시지, 브랜치 전략 헷갈릴 때 |
| `debugging-and-error-recovery` | 버그 재현 안 되거나 원인 모를 때 |
| `browser-testing-with-devtools` | 반응형 확인, 네트워크/콘솔 디버깅 |
| `code-review-and-quality` | PR 전 셀프 리뷰 기준 |
| `code-simplification` | "이 코드 더 짧게 쓸 수 없나?" |
| `incremental-implementation` | 큰 기능 어떻게 쪼개서 만들지 |
| `planning-and-task-breakdown` | 작업 계획 세울 때 |
| `idea-refine` | 새 기능 아이디어 구체화할 때 |
| `interview-me` | 포트폴리오 프로젝트로 면접 준비 |
| `ci-cd-and-automation` | GitHub Actions, 자동 배포 설정 |
| `test-driven-development` | 테스트 작성 방법, 무엇을 테스트할지 |
| `api-and-interface-design` | TypeScript 타입, Props 설계 |
| `observability-and-instrumentation` | 방문자 분석, 에러 추적 설정 |
| `documentation-and-adrs` | README, 코드 주석 기준 |

## 스킬 호출 방법

Claude에게: "web-design-guidelines 스킬 기준으로 이 색상 조합 평가해줘"

## 스킬 없는 작업

스킬에 없는 내용은 직접 물어보면 됨. 스킬은 참조 기준이지 제한이 아님.
