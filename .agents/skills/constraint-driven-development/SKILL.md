# Constraint-Driven Development

## 제약은 친구다

제약이 없으면 결정이 무한하다 → 결정 피로 → 아무것도 완성 안 됨.
제약을 먼저 정하고 그 안에서 최선을 찾는다.

## 포트폴리오 제약 설정 예시

**기술 제약**
- 새 라이브러리 추가: 프로젝트 완성 후로 미룸
- CSS: Tailwind만 사용, 커스텀 CSS 최소화
- 컴포넌트: 50줄 초과 시 분리

**시간 제약**
- 섹션 하나: 2일
- 디자인 결정: 30분 안에 → 그 이상은 과최적화

**범위 제약**
- 페이지 수: 1페이지 (랜딩)
- 섹션: Hero, About, Projects, Contact — 이 4개만

## 막힐 때

너무 많은 선택지 앞에서 막히면:
1. 가장 많이 쓰는 방법 선택
2. 나중에 바꿀 수 있는가 확인
3. 30분 고민했으면 그냥 결정

## 레퍼런스 고정

디자인 레퍼런스 1–2개 고정 후 그것과 비교하며 결정.
매번 새 레퍼런스 찾는 것은 결정 지연의 원인.
