# Planning & Task Breakdown

## 원칙

- 각 태스크는 **독립적으로 배포 가능**해야 한다
- 막연한 "~구현"보다 "~하면 완료" 형태로 명확하게
- 첫 번째 태스크는 항상 가장 작게 — 모멘텀이 생긴다

## 분해 방법

**큰 기능 → 수직 슬라이스**
UI만 먼저 (하드코딩 데이터) → API 연결 → 엣지케이스 처리

**예시: 프로젝트 섹션 추가**
1. 정적 HTML/CSS 레이아웃 (하드코딩)
2. 데이터 구조 정의 (타입/스키마)
3. 데이터 파일 분리 + 렌더링 연결
4. 반응형 처리
5. 애니메이션/트랜지션

## 태스크 크기

- 이상: 2–4시간 안에 완료
- 하루 넘어가면 → 더 쪼갠다
- 30분 이하면 → 묶어도 됨

## 포트폴리오 섹션 체크리스트

계획 전 확인:
- [ ] 이 섹션의 목적(방문자에게 전달할 것)
- [ ] 필요한 데이터/콘텐츠 확보 여부
- [ ] 디자인 레퍼런스 있는가
- [ ] 모바일 레이아웃 고려했는가
